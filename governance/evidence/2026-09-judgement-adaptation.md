# September 2026 Judgement Adaptation

## Plan and authority

Andrew requested a plan followed by implementation of three discussed improvements: challenge familiar reasoning methods when they do not fit; recognise sufficiency without overriding standards or authority; and distinguish emotional or intuitive signals, their explanations and choices between values. This approves the defined repository batch. Personality labels, scores and the private source profile are not included in runtime instructions or this record.

The plan covers:

1. Amend axioms 2 and 3, qualify calibration's preferred methods, and place the three binding behaviours in the existing expansion and quality sections.
2. Review the chat and execution derivations for coverage, preserve the chat budget, regenerate seven detached copies and preserve their wrappers.
3. Add paired behavioural probes, including required-check, deliberate-exploration and routine-execution controls.
4. Update the generic framework lesson, design rationale, coverage map and parent indexes.
5. Check source integrity, exact distribution, navigation, anonymisation and before/after behaviour; obtain a fresh-context critique and report limits separately from results.

The task began with existing uncommitted modifications and deletions. A temporary snapshot captured 101 extant files before this batch. Existing changes are preserved. No task-start file was deleted, renamed or moved. One Python cache generated by a local check was removed, together with its empty directory, after Andrew explicitly approved that exact cleanup. Live deployment, committing and publication are outside this implementation.

Andrew separately approved sending the philosophy, core constitution, condensed contracts, proposed changes and synthetic prompts to Claude for tests and independent review, after automatic approval review initially rejected that disclosure without explicit destination-specific authority.

## Implementation

The three behaviours are implemented within the existing architecture:

| Behaviour | Philosophy and calibration | Binding rule and derivation |
|---|---|---|
| Method fit | Axiom 2 leaves habitual methods open to revision. Calibration tests the fit of abstraction and analogy while preserving the user's work to make the reframe. | Expansion requires task evidence, concrete alternatives and restraint when the familiar method fits; it forbids attributing personality traits or motives. Both condensed bodies carry method fit and the prohibition on invented motives. |
| Sufficiency | Derives from the existing purpose of improving judgement and learning through application; no additional axiom was needed. | Quality Bar identifies diminishing value and the next informative step, while preserving standards, required checks, action authority and deliberate exploration for learning. |
| Experience and values | Axiom 3 admits feelings and intuition as signals without treating their explanations as proof, and distinguishes evidence from value choice. | Quality Bar examines consequential expressed reactions across modes, requires material missing context before questioning, and leaves the value judgement with the user. |

Philosophy and other non-platform documentation continue to rely on Git history. The bootstrap, professional overlay, role charter and voice skill are unchanged by this batch.

## Behavioural evaluation

The responding and grading runner was the installed Claude CLI in safe mode, with all tools, MCP sources, skills and session persistence disabled. Responses used the reported `claude-opus-5` model, medium effort, and a fresh context for each scenario. Only the selected core or marked condensed body was supplied as the operating text. Philosophy, rubrics, governance and drafting history were excluded from responding contexts.

The selected set is L1–L8 plus existing controls H1 (sound execution brief) and C2 (framing invitation). The task-start core was run three times per scenario. After an initial amended-core comparison and detached smoke runs, two failures prompted repairs: one method challenge attributed a motive to the user, and both condensed routes supplied a developed read before awaiting the user's framing. The source now forbids motive attribution in method criticism; both derivations explicitly require asking first and awaiting the reply.

The repaired core was run three times per scenario. Each condensed route was initially run once per scenario, with two additional C2 runs. All L1–L8 passed in those smoke runs. Further C2 failures showed that asking a question while developing a diagnosis still violated the light-invitation boundary. Both derivations now give a concrete request for the user's own one-sentence read; execution explicitly stops after that question. A late H1 response invented a test-design detail to sustain a challenge, prompting an explicit execution reminder to distinguish uncertainty from a defect and never invent supporting facts.

The final chat body was checked on C2 and H1 three times each, and L5, L7 and L8 once each. After the last execution-only repair, C2 and H1 were checked three times each. Other scenario results belong to the earlier recorded candidate; they are not presented as runs of the final execution bytes. The task-start execution body was then checked on the same two controls to distinguish a persistent model failure from a new regression.

Grading used the same model in separate contexts with opaque response IDs hiding version and route. Manual review covered every final C2 and H1 response, alongside spot checks of the other scenarios. It corrected an automated pass that missed invented pilot-staff proximity, and two automated passes that accepted developed analysis as a light invitation. Original automated verdicts and manual dispositions were retained separately. The results below use the corrected dispositions. Initial and superseded candidates are not pooled into final scores.
