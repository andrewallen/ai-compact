# Philosophy-to-Evidence Map

The [axioms](../philosophy/axioms.md) define purposes. The [operating contract](../constitution/02-operating-contract.md) makes behavioural commitments. This map identifies evidence and its limits; it does not mark an unrun scenario as validated.

| Axiom | Constitutional expression | Existing / new evidence | Remaining human or deployment question |
|---|---|---|---|
| 1. Extend thinking; compare with and without the compact | Expansion, mode, quality | B1/B2; M1/M3 conversations; paired no-compact/core conditions | Did the contribution improve the user's understanding and later judgement? |
| 2. Protect independent judgement; revise beliefs and methods | Ownership, exploratory restraint, method fit | C1–C5, E1/E2, L1/L2; shared ownership gate | Can the user explain and defend the conclusion independently? |
| 3. Consequential alternatives, evidence, experience and values | Expansion; Experience and values | B1/B2, L5/L6, M2, T2 | Were the alternatives useful and the value trade-off recognised by the user? |
| 4. Earn ideas through application | Quality; next informative step | L3/L4, M1, T1; human follow-through | Did a retained idea survive use? A plausible experiment is not a result. |
| 5. Memory improves future judgement, under authority | Shift surfacing, continuity, scope | E1/E2, F1–F3, G3; human follow-up | Does authorised retrieval help later judgement? Requires a separately scoped memory test. |
| 6. Go beyond default answers | Consequential lenses and alternatives | B1/B2; no-compact comparisons; contribution score | Is the compact adding value over the same host/model without it? |
| 7. Useful provocation; user control | Challenge, mode, approval | A1/A2, H1/H2, I1/I2, M3 | Is the challenge useful enough to justify interruption? |
| 8. Honest coaching without agreeable drift | Agreement discipline | A1–A3, M3; challenge and friction scores | Is disagreement understandable and useful, including when the user retains their view? |
| 9. Nothing made up; provenance visible | Verification, attribution, tool evidence | Shared grounding gate in every case; J1–J4, K5; calibration anchors | Are source/tool claims actually verified on the deployed route? |
| 10. Usable output without flattening | Partner register; My Voice | D1–D5, K4; execution and friction scores | Does Andrew find the output usable and recognisably his when owned? |

The current automatic registry in [cases.json](cases.json) covers selected text-only cases. It includes diagnostic singles and native conversations; it deliberately excludes real tool effects, skill discovery, live retrieval and long-context durability. Keep those fixtures and run them through an appropriate isolated product harness. A tool-free answer about a hypothetical write cannot establish actual write restraint.

The professional-context cases in [boundary and durability probes](boundary-durability-probes.md) use the explicit `core-overlay` route: G1 tests dormancy, G2 open perspectives, G4 dated context, G5 customer capacity under commercial pressure, and G6 the limits of practitioner evidence. These connect the conditional overlay to the shared grounding, ownership and execution standards. G4 tests uncertainty about a hypothetical future, not successful retrieval; G3 still requires a separate long-conversation setup.

All existing fixture families inherit the [shared rubric](shared-rubric.md). Historical binary scores retain their original meaning. They are not retrospectively converted into full-contract passes. The [protocol](evaluation-protocol.md) separates conformance, change and value; the [human review](human-review.md) supplies evidence that a model cannot provide about the user's learning.
