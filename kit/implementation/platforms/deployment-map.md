# Deployment Map

The cross-product routing guide for AI Compact. Product guides own exact setup and supported controls; [contract maintenance](contract-maintenance.md) owns source coverage, loading combinations and generation. Changing a product's configuration model should require an adapter update, not a constitutional rewrite.

## Contract routes

| Route | Supply | Use |
|---|---|---|
| Configurable chat | Generated [chat contract](chat-contract.md) in the product's instruction settings. | A standalone condensed operating contract. |
| Full operating context | Bootstrap, calibration and operating contract from [constitution](../../constitution/README.md); professional overlay only when relevant. | Sustained work through accessible project files, attachments, paste or filesystem reads. Make reading and application explicit in the host's instruction surface. |
| Defined task | [Execution contract](execution-contract.md), including the task handover. | Bounded analytical or practical work, on any suitable model. |
| Cowork | Supplied core constitution or chat contract, plus the Cowork addendum. | Additional file, planning and connector safeguards. Verify base availability instead of assuming profile inheritance. |

The two shared bodies work without full constitution files and defer to them when supplied, within the host's hierarchy. Addenda and project templates require their declared base. Do not routinely stack both shared bodies with a full core. Exact combinations are maintained in [contract loading](contract-maintenance.md#loading-combinations).

Mode follows the request and preceding context. A model or product can support exploration, execution and refinement; the product label does not select a different constitution. [Model guidance](model-guidance.md) separates dated vendor advice from host controls and local evidence.

## Skills and other capabilities

Supply detailed output craft separately when execution needs it. Shared contracts already carry the voice boundary and compact writing standards. Personal skills remain standard `SKILL.md` folders rather than per-product conversions; client-specific discovery, invocation and permissions still need verification.

The [skills tracker](../skills/README.md) records the adopted working set and brief deployment notes. Retain useful native capabilities and prefer each provider's own additions in its harness; independent skills may be shared where useful and supported. Maintain personal source in the kit and use managed provider distribution for external packages.

The [my-voice marketplace guide](../plugins/my-voice/README.md) owns installation and update commands for Claude, GitHub Copilot and Codex. GitHub publishes generated releases from canonical source; each host controls refresh and activation. Publication does not install the plugin or supply standing constitutional instructions.

Platform baselines own setup and outstanding gaps; [dated evidence](../../../governance/evidence/README.md) records observations. Adoption, availability, source alignment and successful use are distinct. For an authorised live change, identify exact targets and dependencies, preserve a restoration route and verify saved state and relevant use. Compare alternatives when value or interference is uncertain. Ordinary use does not require another formal record.

## Persistent state and account boundaries

A tracker entry or deployment route does not authorise an action. Deliberate persistent changes require scoped approval, including standing instructions, project files, knowledge-store entries and explicit user-visible memory records. A specified change request can supply that approval; narrower safeguards still apply.

Ambient memory and conversation history belong to product settings. Each product guide documents enablement, review and available isolation controls; standing prompts cannot guarantee that a service will not retain or infer context. Use the current host controls rather than treating a mode name as an isolation guarantee.

Credentials, exact trusted roots and account-specific security state stay in the products that hold them. Baselines may record portable settings policy and verification limits, without importing private values into this public repository.
