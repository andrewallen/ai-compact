# Prompts

Lightweight entry points for distinctive ways of working with the model. Copy the relevant prompt into a conversation; it supplements the constitution and active role, never replaces them. Generic analysis and writing standards already belong in the operating contract.

## Catalogue

| Status | Prompt | Purpose |
|---|---|---|
| Previously used pattern; revised wording untested | [Project discovery interview](discovery-interview.md) | Surface goals, constraints and inherited assumptions before planning an unclear project. |
| Experimental | [Five candidate prompts](untested/README.md) | Elicit direction, expose blind spots, learn evaluative standards, test a position and check understanding. |

## Capture and promotion

Create a lowercase, hyphenated Markdown file in `untested/` and link it from that folder's index. Use this minimal shape:

```markdown
# Prompt Name

**What it does.** The useful interaction it enables.

**When to use it.** The situation that calls for it.

## Prompt

> The text to supply, with placeholders where needed.
```

Add notes only for a useful constraint or variation. No frontmatter or separate template is required. Supporting files, a substantial workflow or invocation machinery can justify graduation to a [skill](../skills/README.md).

Experimental status creates no commitment to test or promote. Move a prompt to this folder only after successful live use, evidence-based refinement and a check against forced symmetry, premature production and unsupported ownership. A substantive rewrite must distinguish evidence for the old pattern from the untested new wording.
